# ADR-003：搜索用 SQLite LIKE，不上 FTS5

- 状态：已接受（Accepted），存在明确升级路径
- 日期：2026-10-03
- 决策人：研发

## 背景

F3 搜索需要按关键词匹配标题与正文。SQLite 原生提供 FTS5 全文索引，但引入它有建表、触发器同步、分词器配置的成本。

## 决策

MVP 使用 `LIKE '%kw%'` 对 title/content 全表匹配，不建 FTS5 索引。

## 理由

1. 个人使用场景数据量 <千条，LIKE 毫秒级返回，性能余量大
2. 中文分词场景下 FTS5 默认 unicode61 分词器对中文效果有限，要做好还需要额外工作
3. 数据模型不变，后续升级 FTS5 只是加索引表，无迁移风险

## 后果

- 正面：实现最简、无同步逻辑
- 负面：数据量大时线性变慢；LIKE 无法利用索引
- 触发重评条件：文章数 >1 万或搜索 P95 >200ms（已在技术债 TD-3 登记）

## 关联

- API 契约 `GET /articles?keyword=`；技术债 TD-3
